# Keitaro wrapper

Обёртка над рекламным трекером Keitaro: FastAPI + SQLAlchemy + Alembic, фронтенд на чистом HTML/JS.

1. **Создаватор кампаний.** Принимает название, код страны и оффер. Создаёт в Keitaro кампанию с доменом, группой и источником и два потока:
   - поток 1 — все посетители из указанной страны уходят на `https://google.com`;
   - поток 2 — все остальные уходят на выбранный оффер.
2. **Редактор офферов в потоках.** Изменения копятся в базе обёртки и уходят в Keitaro только по кнопке Push.

## Запуск

Нужен Python 3.11 или новее.

```bash
git clone https://github.com/imronguk-lgtm/keitaro-wrapper.git
cd keitaro-wrapper
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # и впишите KEITARO_API_KEY
alembic upgrade head        # создаёт таблицы
uvicorn app.main:app --reload
```

После запуска откройте http://127.0.0.1:8000. Документация API: http://127.0.0.1:8000/docs.

### Настройки (`.env`)

| Переменная | Что это |
|---|---|
| `KEITARO_URL` | адрес трекера без `/admin`; учебный стенд — `https://keitaro-for-tests.etolegko.com` |
| `KEITARO_API_KEY` | ключ Admin API, берётся в админке Keitaro |
| `DATABASE_URL` | база обёртки. По умолчанию SQLite-файл `wrapper.db`, подойдёт и Postgres |
| `CAMPAIGN_PREFIX` | обязательный префикс названия кампании, например `test_ivanov_` |
| `FALLBACK_URL` | куда отправлять посетителей из выбранной страны (по умолчанию Google) |

## Миграции

Схема БД описана в `app/models.py`, миграции лежат в `migrations/versions`.

```bash
alembic upgrade head                                  # применить все миграции
alembic revision --autogenerate -m "что изменилось"   # создать миграцию после правки моделей
alembic downgrade -1                                  # откатить последнюю
```

Адрес БД Alembic берёт из `.env` (`DATABASE_URL`), см. `migrations/env.py`.

## Как работает редактор

| Действие | Что происходит |
|---|---|
| **Fetch streams** | Загружает кампанию и потоки из Keitaro. Поток без офферов показывается просто как поток, его содержимое не разбирается. Если оффер, который знала обёртка, удалили прямо в Keitaro, он не пропадает, а уходит в архив (серый, с кнопкой Bring back). Неопубликованные правки при этом сбрасываются: источник правды — Keitaro. |
| **Добавить оффер** | Поиск по ID или названию среди офферов Keitaro. Веса пересчитываются (4 оффера → по 25%), поток становится жёлтым: есть неопубликованные изменения. |
| **Remove** | Оффер становится серым, его вес 0%, остальные веса пересчитываются. После Push оффер исчезает из Keitaro, но остаётся в архиве обёртки. |
| **Bring back** | Возвращает оффер из архива, поток снова жёлтый. |
| **Pin** | Закрепляет вес оффера. При любых пересчётах закреплённые веса не меняются, а остаток до 100% делится поровну между незакреплёнными. Сумма закреплённых не может превышать 100%. |
| **Push to Keitaro** | Отправляет список офферов с весами в поток Keitaro (`PUT /streams/{id}`). Поток снова белый. |
| **Cancel** | Отменяет неопубликованные правки. Добавленные, но не опубликованные офферы удаляются из базы, удалённые возвращаются, веса становятся такими же, как в Keitaro. |

Веса целые. Остаток от деления достаётся первым офферам: 100 / 3 → 34, 33, 33.

### Состояние оффера в потоке

Каждая привязка оффера к потоку (`stream_offers`) хранит два флага:

- `included` — оффер должен быть в потоке (так хочет пользователь);
- `published` — оффер сейчас есть в Keitaro.

| included | published | статус |
|---|---|---|
| да | да | активный |
| да | нет | добавлен, ждёт публикации |
| нет | да | удалён, ждёт публикации |
| нет | нет | в архиве |

Поток «жёлтый», если хотя бы у одного оффера `included ≠ published` или вес в обёртке отличается от веса в Keitaro.

## Структура

```
app/
  main.py      — HTTP-эндпоинты FastAPI
  creator.py   — создание кампании и двух потоков
  editor.py    — fetch / add / remove / bring back / pin / push / cancel
  weights.py   — пересчёт весов с учётом закреплённых
  keitaro.py   — клиент Keitaro Admin API (httpx)
  models.py    — таблицы SQLAlchemy
  static/      — фронтенд (HTML + JS без сборки)
migrations/    — Alembic
tests/         — сценарии редактора на фейковом Keitaro
```

## Тесты

```bash
pytest
```

Тесты используют фейковый Keitaro в памяти и SQLite в памяти, поэтому реальный трекер не трогают.
